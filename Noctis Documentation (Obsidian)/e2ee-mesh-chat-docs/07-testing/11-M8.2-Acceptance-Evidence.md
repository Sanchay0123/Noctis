# M8.2 Acceptance Evidence

## Milestone

**M8.2 — Fyne GUI Foundation**

## Status

**🟢 COMPLETE / VERIFIED / APPROVED**

## Scope

M8.2 adds the primary Fyne GUI behind a `gui` build tag and extends the
application service with explicit peer dialing.

## Architecture evidence

- GUI depends on the application service, not crypto/session/routing internals.
- Manual peer entry is used; no DHT or automatic discovery was introduced.
- PeerID, network address and conversation identity remain distinct concepts.
- GUI-visible state excludes private keys, session keys and raw protocol data.
- Routing remains blind to application plaintext.
- Headless backend remains separated from GUI/CGO build requirements through
  the GUI build tag.

## Concurrency/lifecycle remediation

The first M8.2 implementation was rejected because background event handling
mutated GUI state without synchronization and shutdown did not fully coordinate
with the application service.

The remediation introduced synchronized `UIState` for mutable conversation,
peer-list and current-peer state. Event handling updates state under the
appropriate lock before requesting UI refresh. GUI shutdown signals the event
consumer and then stops the application service.

## M8.2-specific tests

Added coverage includes:

- `DialNode` success/failure behavior
- invalid PeerID handling
- deterministic concurrent UI state access with 100 workers
- event processing
- `SendMessage` success/failure
- application/UI shutdown behavior

Reported formatting, vet, tests, race-detector and build validation passed.

## Environment qualification

The GUI runtime was not available for interactive smoke testing in the review
environment. GUI build validation was performed in an environment with the
required native graphical dependencies. The headless Alpine backend remains
separate from those GUI dependencies.

The latest backend Docker E2E rerun was externally blocked by proxy/DNS timeout;
previously approved M8.1 Docker E2E evidence remains authoritative. No code
regression was established by the blocked rerun.

## Security terminology

The project AEAD is **ChaCha20-Poly1305**. No AES-GCM implementation or
AES-GCM terminology is part of the approved source architecture.

## Gate decision

M8.2 was independently audited, remediated and **approved** within the reviewed
scope. Interactive GUI runtime smoke testing remains an evidence limitation.
M8.3 is not authorized by this record.
