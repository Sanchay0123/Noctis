# M8.1 Acceptance Evidence

## Status

**🟢 COMPLETE / VERIFIED / APPROVED**

## Objective

Establish a narrow ApplicationService boundary between the GUI/presentation
layer and the approved crypto, session, mesh and routing implementation.

## Critical security remediation

The initial M8.1 implementation incorrectly decrypted APP_DATA inside
`internal/routing`. This was rejected during security review.

The final implementation changed the routing callback to carry opaque values:

```text
session_id
sequence_num
ciphertext
```

Routing no longer calls `DecryptMessage()`.

Endpoint processing occurs in `internal/app`:

```text
Router
  ↓ opaque ciphertext
ApplicationService
  ↓ Lookup(sessionID)
Session
  ↓ DecryptMessage()
EventMessageReceived
```

Source searches after remediation found no `DecryptMessage` or plaintext
handling in `internal/routing`.

## Session mapping remediation

Peer-to-session mapping removal was made conditional so that stale cleanup of
an older session cannot delete a newer mapping for the same peer.

## Validation

M8.1 retained the approved M6/M7 backend evidence and passed the relevant
application, routing, race and build validation reported during the milestone.

## Gate decision

**🟢 M8.1 APPROVED**
