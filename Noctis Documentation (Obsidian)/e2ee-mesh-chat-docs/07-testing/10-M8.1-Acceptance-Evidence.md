# M8.1 Acceptance Evidence

## Milestone

**M8.1 — Application Service / UI Boundary**

## Status

**🟢 COMPLETE / VERIFIED / APPROVED**

## Scope

M8.1 introduced the application service boundary and the narrow routing change
required to deliver opaque APP_DATA to the local endpoint application.

## Security-critical evidence

- `internal/routing` no longer decrypts APP_DATA.
- Routing passes opaque `session_id`, `sequence_num` and ciphertext upward.
- Endpoint session lookup and `DecryptMessage` occur in `internal/app`.
- Authenticated plaintext is emitted only after successful endpoint AEAD
  processing.
- PeerID-to-session removal is conditional so stale cleanup cannot delete a
  replacement mapping.
- Security searches reported zero routing references to `DecryptMessage` and
  zero routing references to plaintext handling.

## Functional evidence

The application service provides the reviewed operations for local identity,
manual dialing, conversation management, message sending, lifecycle and
application event subscription.

Previously approved Docker Alice→Bob→Carol evidence demonstrated multi-hop
message delivery while preserving the relay-blind E2EE boundary. The M8.1
remediation preserved that architecture.

## Validation

```text
gofmt
```

M8.1-specific tests cover application delivery, service behavior and the

## Gate decision

M8.1 was independently audited, remediated and **approved**. The critical
finding from the first implementation—plaintext decryption in the router—was
closed before approval.
