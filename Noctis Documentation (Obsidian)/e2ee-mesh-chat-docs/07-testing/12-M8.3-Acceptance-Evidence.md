## Shutdown remediation

The final GUI event consumer is tracked by a `sync.WaitGroup`.

```text
GUI exits
   ↓
close(shutdown)
   ↓
wg.Wait()
   ↓
event consumer exits / wg.Done()
   ↓
ApplicationService.Stop()
```

This provides an explicit lifecycle guarantee rather than relying on process
termination.

## Remediation 4 — Transport Admission Modernization

The first live connection attempt previously failed deterministically because
the inbound listener required `ExpectInbound` pre-authorization before accepting
the authenticated handshake. Remediation 4 removed that transport admission
dependency while preserving bounded pending-handshake admission, handshake
timeout, frame-size validation, authenticated identity verification, expected
PeerID checking and duplicate arbitration.

New regression coverage includes:

- `TestListener_AcceptsUnknownPeer` — first connection succeeds without
  pre-authorization.
- `TestExpectedPeerIDStillEnforced` — authenticated identity mismatch remains
  rejected by the ApplicationService.

The transport now admits inbound connections into the bounded authenticated
handshake rather than requiring out-of-band pre-authorization. This increases
exposure to unauthenticated handshake attempts but retains bounded concurrent
handshake work and handshake lifetime. It is not a claim of immunity from DoS.

## Final Live Acceptance

After Remediation 4, clean two-node GUI instances were tested on
`127.0.0.1:8000` and `127.0.0.1:8001`. Both possible first-initiator
directions succeeded. Secure-session establishment and bidirectional
encrypted messaging succeeded. Repeating Add Peer on an already securely
connected peer produced the idempotent existing-connection behavior without
disrupting the conversation state.

**Live acceptance: PASS. M8.3 is formally closed.**

## Known limitations

Timestamp and message-order behavior were implemented but were not directly
covered by dedicated tests in the final evidence report.

Docker regression could not be verified because dependency resolution inside
the Docker build environment was blocked by external proxy/DNS timeouts.

These limitations do not alter the approved backend security evidence.
